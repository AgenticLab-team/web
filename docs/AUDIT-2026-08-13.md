**读者**：要动这些代码的人
**性质**：**现状**（2026-08-13 当天的一次性核对，不是活文档）
**最后核对**：2026-08-13

> 这份是**某一天的体检报告**，不描述现状之后的变化。
> 修掉一条就在这里划掉它，或者干脆整份作废重做一次 ——
> 一份半新半旧的审计报告比没有更糟。

## 一、界面为什么看起来烂

设计系统本身写得很扎实 —— 尺度、动效三档、0.5px 发丝线、
`prefers-reduced-motion` 的兜底，都想过。问题不在审美，在**层叠**：
有一批规则写下来之后**从来没有生效过一次**。

这四条都不是「写得不好看」，是**写好的东西没到屏幕上**。

### 1. 本地开发环境整站 500 —— 起因是一句测试断言里的提示文案

`tests/visual-consistency.test.ts:64`

Tailwind v4 没有 `content` 配置，它**扫全仓库的纯文本**找候选类名，
`tests/` 也在里面。那句给人看的提示写成了圆角类名的形状、值里带着竖线，
于是 Tailwind 真的照着生成了一条 `border-radius: var(--a|b)` —— 而它不是合法 CSS。

两边表现完全不同，这也是它活得下来的原因：

- `next build` 里 lightningcss 把它咽了下去，只留一条没人用的死规则，**构建成功**，线上正常；
- `next dev` 的 CSS 解析器直接抛错，整份 `src/app/globals.css` 编译失败，**每一个页面 500**。

也就是说：如果最近是在本地 `npm run dev` 看的界面，那看到的根本不是这个站。

**已修**，并加了守卫：扫全仓库，禁止任何「工具类-方括号」形状的任意值里出现竖线。

### 2. 三十个后台页面被压在 590px 里

`src/components/shell/AppShell.tsx` → `src/app/globals.css`

栏宽的默认值写在 `<main>` 的内联 `style` 上，而**内联样式赢过任何普通样式表规则**。
globals.css 里那条 `main:has([data-dense])` 是专门为后台写的加宽覆盖 —— 它一天都没生效过。

在 1900px 的屏幕上，权限矩阵、审计日志、用户列表全部挤在 832px 的正文栏里，
减掉 13rem 的后台目录之后只剩约 590px，两侧是大片空白 ——
这正是那条 CSS 注释自己描述的、它本该修好的症状。

守卫测试当时是绿的：它分两半各自字符串匹配了默认值和覆盖。
**两个字符串都在，不代表它们之间的关系成立。**

**已修**：默认与覆盖收进同一个文件、同一种优先级（`main#main` 与
`main#main:has([data-dense])`，靠特异性分胜负）；测试改成断言这段关系本身，
并禁止栏宽退回内联 style。

### 3. `font-medium` 在约 190 处是空写的 —— 包括每一个按钮

`src/app/globals.css`（`.t-*` 排版阶梯）

排版阶梯的每个类都声明了 `font-weight`，而它们全都**在 `@layer` 外面**。
CSS 的规则是「层外的一律赢过有层的」，Tailwind 的工具类都在 `utilities` 层 ——
所以 `class="t-subhead font-medium"` 里那个 `font-medium` 什么也不做。

**这就是「没质感」的字面来源。** 共享按钮返回的是 `t-subhead … font-medium`：
全站 primary / neutral / danger 按钮都在按 400 而不是 500 渲染，标签比设计稿明显轻。
药丸标签、配色开关、榜单升降数字同理。

反方向也存在：`.t-title*` 是 600/700，压在它们上的 `font-medium` 会让文字比预期**更重**。

**已修**，但先把「会不会改坏」数了一遍 —— 因为这次没有浏览器可用，
只能靠静态枚举把风险排除干净。结论是**没有任何一处会变轻**：

- `t-headline` 的 18 处调用**一处都没带**字重工具类；
- 标题档里只有 2 处带（`admin/PruneRunner.tsx` 与 `members/[wxId]/page.tsx`），
  而且都是 `t-title3 font-semibold` —— 600 对 600，纹丝不动；
- 全站 `font-normal` 的 17 处，要么配 `t-caption` / `t-caption2`（400 对 400，不变），
  要么压根没有 `t-*`（那几处在 `<th>` 上，压的是浏览器默认的 bold，本来就生效）；
- 全站**没有任何** `font-light` / `font-thin` / `font-extralight`；
- `.t-group-label` 的 16 处调用只额外带了 margin / padding，
  它声明的字号、字重、颜色没有一处被工具类碰过。

也就是说这次改动只有一个方向：约 190 处文字**回到它的作者亲手写下的那个字重**。
字号、行距、颜色、间距一律没动，所以不会引起重排。
`tests/css-layers.test.ts` 也一并改了 —— 原来那两条断言是「类名的下标大于
`@layer components {` 的下标」，而现在文件里有两个层块，`indexOf` 只找第一个，
**那条断言会变成永远为真**。改成了「把层块整个抠掉，剩下的部分里不许出现这些类名」。

即便如此，这仍是一次全站视觉变化，**上线前请自己扫一眼几个主要页面**。

### 4. 权限矩阵在手机上被裁掉，而且划不动

`src/components/admin/MatrixEditor.tsx`

容器原来写的是 `inset-group overflow-x-auto`。同样是层外赢层内：
`.inset-group` 的 `overflow: hidden` 压掉了工具类的 `overflow-x: auto`，算出来是 hidden。

360px 的手机上，表宽 36rem（576px），两百多像素被直接裁掉，
**没有滚动条也划不动** —— 管理员永远够不到后面几个身份组的列。
而这不会有人来报：看不见的列看起来就像「不存在」。

**已修**：设计系统里补了 `.inset-group-scroll` 这一档（和 `.inset-group`
共用同一份底色与圆角声明，只有溢出行为不同），调用点换过去。

## 二、其余已核实的发现

13 个方向并行找，每条再单独派一个「专门来推翻它」的验证者，默认存疑即否决。
77 条进入验证，**66 条活下来，10 条被推翻**。

严重度按「是否已经在伤害真实用户」判，不按修复难度。

### 登录与绑定

**手动绑定这条路 100% 无效，而且绑定码还能被别人抢走**（高危）
`src/lib/auth/bind-queue-actions.ts:120`
`manualBindAction` 不把 `bind_codes.status` 从 pending 改成 used，而状态机第一分支就是
pending → 直接返回「等待验证」。管理员看到「已绑定」，用户那边一直转圈到过期。
附带：这一行仍是 pending 且未过期，群里任何人再发一遍这个码就能把它抢过去。
→ 同一次 update 里补上 `status: "used"` 与 `usedAt`，where 收紧成 `and(id, status="pending")` 防并发。

**退出登录不结束「以他人身份预览」**（中）
`src/lib/auth/session.ts:215`
`revokeCurrentSession()` 不碰 `al_preview`，而预览解析全程不看会话是否还在。
首页、`/forum`、登录页都会继续按被预览者渲染 —— 登录页那条 `if (user) redirect`
会把刚登出的人以别人的身份弹回首页。共用电脑上，下一个人登录后预览 cookie 仍在
30 分钟内，此时 `/me/security`（别人的登录历史和 IP）真的能打开。
→ 登出时结束预览并删 cookie；建新会话时也清一次。

**账号锁定可以被攻击者无限续期**（中）
`src/lib/auth/password-login.ts:184`
锁定命中时也写一条 `success:false` 的失败记录，而解锁判定用的是「最后一次失败」——
每次「被锁定拒绝」都把 15 分钟窗口重新推后。每 10~12 分钟发一次请求
（约 5~6 次/小时，远低于 20 次/IP/小时的限流）就能把一个人永久锁死。
代码注释里写着这正是它要避免的事。
→ 统计失败次数时跳过 `failureReason === "locked"` 的行。

**「换个账号试试」在 5 分钟内是个空按钮**（中）
`src/app/api/auth/bind/status/route.ts:24`
判定为「不是群成员」时不删 `al_bind` cookie，于是点这个按钮走 resume 分支，
拿回的是同一个已经归属别人的旧码，两秒后又弹回原样。
→ `not_member` 分支返回时带上 `cookies.delete("al_bind")`。
（注意：「重新获取」那条路没坏，别一起改。）

### 权限

**预览态可以真的写数据 —— 写操作藏在辅助函数里时静态检查看不见**（高危）
`src/lib/admin/user-actions.ts:53` 等 6 处
覆盖率检查器只认函数体里字面出现的 `.insert(` / `.update(` / `.delete(`，
所以「把写委托给辅助函数」的 action 被整个跳过。站长以他人身份预览时点「调整积分」
会**真的写库**，而审计日志记的是被预览的那个人 —— 他从没做过这件事。
涉及 `adjustPoints`、`revokeUserSessions`、`changeSetting`、`rollbackSetting`、
`resetSetting`、`refund` 六处。
→ 六处换成 `requireWritableAdmin`，并让检查器认得出「调用了已知会写库的委托函数」，
否则下一个同形状的还会漏。

**「不能移除最后一个站长」把过期和被封的授权也算成在册持有人**（中）
`src/lib/admin/user-actions.ts:270`
这里只过滤 `revokedAt`，而真正决定权力的那两处还要求未过期、持有人未被封。
于是：站长先封掉前任站长 B（授权行不动），再撤掉自己的 owner —— 护栏数出来是 2，放行。
撤完全站没有任何有效站长，只能改数据库救。
→ 直接复用 `role-admin.ts` 的有效持有人计数，并排除 status 非 active 的人。

**提交可见性提升申请没有校验申请人看不看得到这篇帖子**（中）
`src/lib/admin/escalation-actions.ts:45`
注释写着「任何能看到这篇帖子的成员都可以提」，代码里没有可见性判定。
因为它和别的 action 同处一个 `"use server"` 文件，Next 会给每个导出注册 action id ——
**没有 UI 调用它也照样可达**。后果是往审核队列插入攻击者写的任意文本，
外加通过不同的报错文案对不可见帖子做状态探测。
→ 取到 post 之后、检查之前补可见性判定，不可见时返回同样的「帖子不存在」。

**存储页三处权限点互相不一致**（中）
`src/lib/admin/nav.ts:64`
导航声明 `system.dashboard`、页面守卫要 `system.storage`、裁剪区块用 `system.settings`
判显示、三个 action 又要 `system.storage`。结果：审计员看得见导航但点进去被弹回
（一条每次都回到原地的死链）；内置「管理员」持有 `system.storage` 却因为被拒了
`system.settings` 而**永远看不到裁剪按钮** —— 全站只有站长能用这个功能。
→ 三处收敛到 `system.storage`，`/admin/flags` 是同一形态，一并对齐。

**审计日志按动作筛选用前缀 LIKE，和筛选条上显示的条数对不上**（低）
`src/lib/admin/audit-query.ts:72`
筛选条的计数是精确 groupBy，点进去查询却是 `like("前缀%")`。库里有 `role.grant` 和
`role.grant.admin` 这类前缀包含关系 ——「授予管理员」这种最该单独盯的记录被混进普通筛选里。
`?action=%` 会命中全表。
→ 拆成两个显式参数（精确与前缀）。注意 `/admin/users` 那个手写链接正是靠前缀行为
同时覆盖 `user.delete.self` 的，直接换成精确匹配会静默漏掉自助注销。

### 可见性

**`/members/by/<id>` 把别人的 wx_id 直接交出去，不查有没有共同群**（高危）
`src/app/members/by/[userId]/page.tsx:56`
这条重定向只判断「有人登录了」。目的页会 404 —— 但 wx_id 已经在 `Location` 头和
地址栏里了，**重定向本身就是泄露**。而 `/projects` 给每个同意展示的建设者都渲染了
这个链接、完全不过群，连一个群都不在的 external 账号也能拿到。
拿到 wx_id 就能在微信里加人，这正是整套 `/members/by` 间接层存在的理由。
→ 重定向之前先跑一遍目的页那条判定，不可见就 404。

**`/projects` 列出成员的昵称和头像，同样不过共同群**（中）
`src/lib/github/projects.ts:139`
开关的原话是「同群的人打开你的主页时能看到」，而这一页把同一份数据发给了每一个登录账号。
这是**同意范围被越过**，不只是注释过期。
→ 加 viewer 参数并与可见的群成员取交集；「收录了 N 个项目，来自 M 个人」也必须
跟着变成按 viewer 计算，否则又泄露了存在性。

**成员目录的「本周活跃」是全站口径**（中）
`src/lib/members/queries.ts:342`
用的是不分群的最后发言时间。你和他只共一个 A 群、他在 A 群八个月没说话，
但天天在你看不见的 B 群说 —— 目录仍然显示「本周活跃」。主页那边明确拒绝这么做，
注释就写在那儿。
→ 限定在共同群里算一次 `max(ts)`（一条 group by 查询，不引入 N+1）。

**两个私有的 `myGroupIds` 各写一份，都漏了 `syncEnabled`**（中）
`src/lib/members/queries.ts:140` · `src/lib/links/queries.ts:105`
机器人被移出群之后同步开关翻成 0，而名册不再同步、`left_at` 还是 null。
于是成员目录仍然显示「1 个共同群」，点进去 404；`/links` 仍然显示那个群里分享的链接 ——
判断单条链接可见性的那个函数用的也是这个漂移过的实现。
→ 两处都删掉，改调 `visibleGroupIds(user)`。

### 论坛

**悬赏可以重复发放：换一个采纳对象就再付一次**（高危）
`src/lib/forum/qa.ts:90`
幂等键是按*回复* id 算的，而撤销采纳既不清零悬赏也不冲正。
「采纳 A → 取消 → 采纳 B」把同一笔悬赏付给两个人，提问者只被扣过一次，
还能对 C、D… 无限重复。积分流水是这个站唯一的硬通货，这里是凭空增发。
→ **已修**：幂等键从「按回复」改成「按帖子」（`bountyAwardKey`），换个采纳对象也是同一个键；
同时堵住反方向 —— 结算过的悬赏不许再追加，否则那笔钱会照常扣走却发不出去，分反而蒸发；
并把发放挪到落采纳**之前**且检查返回值，失败时什么都不改（原来是静默吞掉的）。

**删了再撤销，会把定时帖当场发出去（而且一条通知都不发）**（高危）
`src/lib/forum/manage.ts:471` 与 `:246`
两处 restore 都无条件写 `status="published"`，不看还挂着的 `scheduled_at`。
定时到周五的帖子被删一次再恢复就是周一公开；因为它不再是 draft，
定时发布器永远不会再处理它，关注该作者/版块的人一条通知也收不到。
版主删了再恢复触发得更容易。
→ restore 要回填删除前的状态，不能一律 published；
注意「撤回成草稿」那类没有定时时间的草稿也要在 `/me/drafts` 里有地方可去。

**版块版主在自己版块里打不开被隐藏／删除的帖子**（高危）
`src/app/(app)/forum/p/[id]/page.tsx:97`
帖子页建 viewer 时没传 boardId，而带 scope 的角色对不带 scope 的资源一律不匹配 ——
板块级版主的「可管理」恒为 false。她自己隐藏的帖子自己打不开，
也就点不到「恢复」（全站唯一入口）。全局管理员一切正常，
所以这个洞只砸在真正的版主头上。
→ 先查出帖子所在版块再建 viewer；`generateMetadata` 和 opengraph-image 是同一个问题。

**论坛搜索不按相关度排，按表的物理顺序排**（高危）
`src/lib/forum/search.ts:99`
bm25 算出来的分只用于同帖去重，最终顺序来自全表读取的表顺序，
而且是在这个顺序上截断 limit 的 —— 标题精确命中的那篇可能根本不在返回里。
→ 按 score 排出有序 postId 列表，取回后按该顺序遍历；可见性过滤仍要在截断之前。

**每次搜索都把 posts 整张表读进内存**（中）
`src/lib/forum/search.ts:101`
没有 where。只为了留下不到 160 行，把全表所有列反序列化成 JS 对象 ——
而正文和渲染后的 HTML 这两列在这个函数里一个字都没用到。
→ 加 `inArray` 过滤并只 select 真正用到的列。

**`reply_count` 只加不减，删一条回复就永久偏高**（中）
`src/lib/forum/undo.ts:34`
帖子页标题写「0 条回复」，列表上同一篇仍显示 3 —— 同一屏两个矛盾的数字。
更实际的后果：「没人答」排序按这个计数，真正无人回答的提问永远排不进去；
热度分里也给了它一份永不衰减的虚高权重。
→ 收口成一个 `recountPostReplies()`，四条路径统一调用
（hidden 和 collapsed 也要一起想清楚，所以不能用 ±1 的写法）。

**「有人回复我的回复」这类通知从来不产生，开关是死的**（中）
`src/lib/forum/notify.ts:208`
扇出只发三类，从不看新回复的 `parentId`。被直接回复的那个人只能靠「帖子订阅」收到 ——
而那一路是可以单独关掉的，两个开关在设置面板上还挨着。
于是有人特意留着「有人回复我的回复」，结果一条也收不到。
→ 把 parent 回复的作者传进扇出，插一段 `reply_to_reply` 并加入去重集合。

**通知设置面板漏渲染一整个分区**（中）
`src/components/notifications/PrefsPanel.tsx:66`
要渲染哪几个分区是手写的第二份清单，漏了 `following`。
而分区的标题和说明文案在数据里明明写好了 —— 说明它本该显示。
「关注的人/版块有新帖」站内那份默认开着且关不掉，推送那份默认关着且打不开。
→ 别写第二份清单，从数据推。

**没人在线时轮询水位线不前进**（中）
`src/lib/notifications/live.ts:293`
空窗期直接早退，水位线停在原地，积压的通知在有人连上的下一轮被当成「新动静」
一次性派发 —— 而且这条查询不过滤已读，昨晚在手机上点掉的那些会再弹一遍。
→ 早退那一支也把水位线推到现在；顺带给查询补上未读过滤。

**编辑器的「每 3 秒存一次本地草稿」在持续打字时一次都不触发**（低）

### 积分

### 同步与检索

**语义索引会永久丢掉「接在最后一个窗口后面」的消息**（高危）
`src/lib/search/semantic.ts:154`

**群「日均消息数」按有消息的天数除**（中）

**成员页骨架屏漏了搜索框，数据到达时整页往下跳**（低）
`src/app/(app)/members/loading.tsx:7`
仓库里本来就有 `SearchBarSkeleton`，另外三个有搜索框的页面都用了。
实际缺口不止搜索框：真实页面渲染**两排**药丸，骨架只画了一排，
还可能多出一条提示横幅。跳的那一帧，恰好是人伸手去点药丸的那一帧。

### Next.js

**换版块之后第一次自动保存必然报「另一台设备上有更新的草稿」**（高危）
`src/components/forum/use-server-draft.ts:57`
乐观并发用的 base 只在首次渲染时取一次，换版块时不重新同步 ——
于是它带着**上一个版块**的时间戳去比对，凭空撞出一个不存在的冲突。
反方向更隐蔽：保存成功会把 base 推到当前时刻，此后切到另一个版块保存时，
别的设备写的更新草稿会被**无声覆盖**。
→ scope 变化时重新同步 base 并清掉待发；注意要一并处理正在飞的那次保存，
否则会用新 base 配旧 scope。

**相对时间用服务器时区算，日期可能整整差一天**（中）
`src/components/forum/PostList.tsx:419` + 7 处同类
超过 7 天走 `toLocaleDateString` 且不传时区，「今年与否」也在服务器本地时区判。
部署脚本和 systemd 单元里都没有钉 TZ。8 月 13 日 01:00（+08）发的帖子在 UTC 机器上
渲染成「8/12」，而且这段文本是烤进 RSC 载荷的，浏览器不会纠正它。
`DONE.md` 里记着同一类 bug 已经上线过一次。
→ 传社群时区，年份也在同一时区取。另有 7 处相同遗漏应一并修。

**搜索上下文里的消息时间用的是浏览者所在时区**（中）
`src/components/search/MessageHitList.tsx:127`
在洛杉矶展开一条命中显示 17:30；点「在群聊记录里打开这一条」，那一页显示 08:30 ——
同一条消息两个时间。而搜索自己提供的日期筛选是按东八区切的。

**日志页的搜索防抖会把刚点上的筛选条件抹掉**（中）
`src/components/api/LogFilters.tsx:113`
防抖回调闭包捕获的是点击之前的 URL 快照。打字 150ms 后点「失败」，
再过 150ms 定时器触发，把 URL 换回没有 status 的版本 —— 分段控件当场弹回「全部」。
→ 在定时器里读实时 query string。顺带：那条 eslint-disable 的理由在 Next 16 里
已经不成立了，`useSearchParams` 现在是记忆化的。

**`getCurrentUser` 没有按请求记忆化：一次页面渲染查 5 次、写 5 次**（中）
`src/lib/auth/session.ts:158`
布局、外壳、`generateMetadata`、页面主体、记录浏览各调一次，
每次都重读 cookie、跑一次 join、再写一次 `lastSeenAt`。
（WAL + `synchronous=NORMAL`，所以是廉价追加而不是锁竞争 —— 但它乘在每一次渲染上。）
→ 用 React 的 `cache()` 包一层。所有改变会话的地方都是独立的 route handler，
不会在渲染中途变身份，所以是安全的。`resolveSession` 本身别包 ——
有测试依赖它每次都真的执行。

### 重复与性能

**每一次权限判定都要全表读一遍 roles，并重查一次授权**（中）
`src/lib/rbac/can.ts:83`
一次判定三条语句。帖子页光是算「这篇帖子我能做什么」就调 6~7 次，
外壳的导航树又跨三处各跑一遍；发帖页那个是*每个版块*调一次，会随数据增长。
→ 只把 roles 的 key→id 映射做成全局缓存（沿用现成的失效函数）。
**授权和例外那两条不能进全局缓存** —— 它们按过期时间过滤，
进程级缓存会让已撤销/已过期的权限一直活着；那两条要按请求记忆化。

**「我能看哪些群」每次都顺带数一遍消息总数，而这个数只有一页在用**（低）
`src/lib/queries/visibility.ts:57`
所有权限判定都走它，然后把这个 count 扔掉。最夸张的是欢迎页：
每个群调一次，而每次调用又把所有群都数一遍。有覆盖索引，今天是毫秒级 ——
属于会随数据长大的结构性浪费，不是现在的卡顿。

## 三、看过真实截图之后的复核

装上无头 Chrome、灌合成数据、把八个页面 ×（桌面/手机）×（亮/暗）截了 32 张之后，
对着图又列了七条「界面问题」。**读完代码之后其中四条不成立** ——
记在这里，因为「凭一张截图判一套有理由的设计」本身就是这次最容易犯的错。

**不成立的四条：**

- **版块区右下那块空白**：以为是 grid 少了一格。实际上那里用的是
  `sm:columns-2`（CSS 多栏），而且注释明确写了为什么不用 grid ——
  就是为了避开我以为存在的那个洞。三组等高内容在两栏里平衡排布，
  必然一栏两组一栏一组。那是多栏排版的正常结果。
- **帖子列表每行长得一样、行距太松**：是刻意的。`PostList` 的注释写着
  「密度是刻意的 —— 这些东西的价值在于一屏能扫掉十条」，
  区分度交给 `DeepList`（卡片 vs 密行）去承担，不靠给每一行加装饰。
- **首页两套统计卡长相**：其实是同一个 `StatTile`，
  只有「我的排名」那一格加了 `accent`。
- **右栏三张卡太占地方**：那是右栏（`aside`）在 `lg` 上竖排，
  窄屏时是 `grid-cols-3` 横排。为一条窄栏做的选择，是对的。

**成立并已修的两条：**

- **同一篇帖子在半屏内出现两次** —— 上面「坐下来读」一张卡，
  紧接着「最新讨论」第一行又是它。精华通常也刚发不久，所以这不是偶发，
  是只要有新精华长文就会撞上。`/forum/deep` 早就用 `seen` 去重了，
  主论坛页没跟上。已补，并且多取几条再切回 15 ——
  直接过滤的话时间线会悄悄少几行。
- **后台身份组每行中间空着九百像素** —— 优先级被 `flex-1` 顶到最右。
  这是**上面那条栏宽修复带出来的副作用**：窄栏时间隙只有两百多像素，
  看不出来。列表本来就按优先级降序排，数字是印证不是用来比的，
  所以撤掉撑杆让它跟在那一簇后面。

一个修复照出另一个地方的问题，这次出现了两回（另一次是 CSS 编译好了之后
才露出 instrumentation 的 Edge 运行时告警）。

## 附：怎么在本地把界面跑起来看

`next dev` 的 500 修掉之后就能跑了，但需要一份数据。
`scripts/seed-ui.ts`（`npm run seed-ui`）会灌一份**合成**数据 ——
不碰任何真实群数据，而且刻意往极端处填：三十字的昵称、纯 emoji 的名字、
六位数积分、六十层的楼、空的版块、没有任何回复的帖子。
界面的毛病都藏在这些地方，用「刚好合适」的假数据看界面等于什么都没看。

它会在最后打印一个会话 cookie，贴进浏览器控制台就是登录态。

前置：`.env.local`（`NEKOBOT_API_KEY` 随便填一个非空值即可，
上游不可用时 `npm run bootstrap` 会自己跳过）→ `npm run bootstrap` → `npm run seed-ui`。
