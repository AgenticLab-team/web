# 站点作为 OAuth 提供方

> **读者**：要实现或 review 这套东西的人
> **性质**：**打算**（尚未实现）
> **最后核对**：2026-08-13

让第三方应用可以「用 Agentic Lab 账号登录」，并代表用户调开放 API。
应用由**管理员创建**，不开放自助注册。

---

## 一、这件事的危险在哪

先说清楚，因为后面每一条设计都是从这里推出来的。

这个站唯一的门是微信群：账号只能靠在群里向机器人发验证码建立。
**OAuth 是在这扇门旁边开一个窗口** —— 它不发新账号，但它把
「以某个成员的身份行事」这件能力交给了一段我们没写的代码。

三条具体的危险：

1. **钓鱼。** 一千六百人的群里发一个链接，写着「授权登录领积分」，
   会有人点。而授权页长得和真的一样 —— 因为它**就是**真的。
   OAuth 的钓鱼不靠伪造页面，靠伪造**应用**。
2. **`groups:send` 会往群里发东西**，而署名是机器人。
   现有注释已经写明：令牌泄漏的后果不由泄漏者承担，由这个社区承担。
3. **群成员关系是隐私**。「谁和谁在同一个群」不能通过任何新口子泄出去。

---

## 二、五条不可协商的

### ① 它不发账号，一行都不写

和 GitHub 回调那条同源：**没登录就跳登录页，绝不建号、绝不发会话**。

「只有群成员能登录」如果在这里被绕过去，等于把整个站对全世界开放，
而且没有任何外部症状 —— 站长自己点一下是能进的。

实现上这意味着 `oauth/authorize` 里不许出现 `createSession`、
不许 `insert(users)`。照 `tests/github-oauth.test.ts` 的做法逐条钉死。

### ② `groups:send` **不进 OAuth**

默认不可申请。理由不是「危险」，是**它会让审计说谎**：

逐群发送授权是站长发给**一个具体的人**的，理由那一栏写着
「他在维护打卡机器人」。一旦这个 scope 能被第三方应用拿到，
代发日志里仍然写着「张三」，而真正按下发送的是一段谁也没 review 过的代码。
那条审计记录从此不再回答它本来要回答的问题。

**如果确实要开**，三个条件同时满足才行，缺一不可：

- 管理员在这个应用上单独勾了「允许申请代发」
- 用户本人已经持有那个群的逐群授权（OAuth 不能凭空产生授权）
- **署名要同时写出应用名**：`本消息由「张三」通过「某某应用」使用 AgenticLab.sh 代发`

第三条是关键：署名的意义是让群里的人知道是谁让机器人说话，
少了应用名这句话就是不完整的。

### ③ 应用只能管理员创建

不开放自助注册。这不是嫌麻烦 —— **自助注册的 OAuth 提供方等于
给钓鱼者发了一个官方授权页**。管理员创建意味着这份名单是被看过的。

代价是加应用要找站长，这是对的代价。

### ④ `redirect_uri` 精确匹配

注册什么就只能用什么。不许通配、不许前缀匹配、不许子路径。
不许带 userinfo（`https://user@evil/`）、不许带端口跳变。

这条在这个仓库里已经交过学费：`lib/github/link-refs.ts` 顶上那段注释
记的就是同一类问题（host 只做全等比较）。照抄那套判定。

### ⑤ 只有 Authorization Code + PKCE

- **没有** implicit（token 直接进地址栏 → 进浏览器历史、进 referer、进日志）
- **没有** password grant（那等于让第三方收集我们的密码）
- PKCE **强制**，公开客户端和机密客户端都要 —— 不给「要不要开」这个选项，
  因为它总会被关掉

## 三、架构上最重要的一个决定

> **OAuth 授权完之后，发出来的是一把和 `al_` 一模一样的令牌。**

不新建第二套令牌体系。理由：

站里已经有一条完整的路 —— `authenticate()` 验令牌和 scope、
`sendAllowance()` 按人限流、`recordSend()` 留痕、
「我的 → 开放 API」里可以撤销和看日志。

另起一套的话，这些每一条都要重写一遍，而**重写出来的那份迟早
少判一样东西**。这个仓库已经因为「同一件事两份实现」吃过好几次亏
（发帖规则、分页边界、图标表）。

具体做法：`api_tokens` 加两列 —— `app_id`（哪个应用换来的，
自己建的令牌为 null）和 `expires_at`。验令牌那条路一个字不改。

好处是免费得到的：
- 用户在「我的 → 开放 API」里同时看见「我自己建的」和「我授权的应用」
- 撤销走同一个按钮
- 代发日志里那一行本来就能显示来源

## 四、流程

```
① 应用把人送来
   GET /oauth/authorize
     ?client_id=...&redirect_uri=...&response_type=code
     &scope=me:read+forum:read&state=...
     &code_challenge=...&code_challenge_method=S256

   没登录 → 跳 /login?next=<原地址>   ← 绝不发会话
   已登录 → 渲染同意页

② 同意页（这一页是整套东西的安全边界，见第五节）

③ 用户点「同意」→ 302 回 redirect_uri?code=...&state=...
   code 一次性、60 秒过期、绑死 client_id 和 code_challenge

④ 应用后端换令牌
   POST /oauth/token
     grant_type=authorization_code&code=...&code_verifier=...
   → { access_token: "al_...", expires_in, refresh_token, scope }

⑤ 之后就是普通的开放 API 调用，走 authenticate()，
   和用户自己建的令牌**没有任何区别**
```

**刷新**：refresh token 一次性轮换。检测到复用（同一个 refresh 用两次）
就把这条授权整条撤销 —— 复用只有两种可能，要么应用写错了，
要么令牌被偷了，两种都该停下来。

---

## 五、同意页要说清楚什么

这一页是唯一挡在钓鱼和用户之间的东西，所以它的内容是安全设计，不是文案。

必须显示：

- **应用名**，以及**谁批的**（管理员昵称）—— 「这是站里认可的应用」
  这件事只有站长背书才有意义
- **令牌会送到哪个域名**（`redirect_uri` 的 host，加粗）。
  这是唯一决定令牌落到谁手里的东西，而用户从来不看地址栏
- **逐条列出 scope 的人话说明**，用现有 `SCOPES` 里的 `label`/`detail`，
  危险的（`danger: 1`）单独标出来
- **这不是登录我们的站** —— 说明它是「把你的身份借给这个应用」

必须有的行为：

- scope 变了要**重新同意**（不能靠上次的同意悄悄扩权）
- 「拒绝」和「同意」等大等重，不做视觉诱导
- 同意/拒绝都留审计

## 六、要新增的表

```
oauth_apps          id, name, client_id, client_secret_hash, redirect_uri,
                    owner_admin_id, allow_send(默认 false), description,
                    created_at, revoked_at

oauth_grants        用户 × 应用的长期授权（scope 集合、何时同意的）
                    撤销 = 连同它签出的所有令牌一起失效

oauth_codes         一次性 code：60 秒、绑 client_id 与 code_challenge、
                    用过即删（不是标记已用 —— 删掉才不会有第二次机会）

api_tokens          + app_id, + expires_at
```

---

## 七、这套东西**不**做什么

- 不做 OpenID Connect（没有 id_token、没有 discovery）。
  需要的时候再加，现在加等于多一份要维护的规范
- 不做 client_credentials（应用自己的身份）——
  这个站里所有能做的事都属于某个人，没有「应用自己」这个主体
- 不做 device flow
- 不做动态注册（那就是自助注册，见 ②③）

---

## 八、验收要钉住的（测试）

- `/oauth/authorize` 和 `/oauth/token` 里不出现 `createSession` / `insert(users)`
- 未登录访问 authorize → 跳登录，**不带任何 Set-Cookie 会话**
- `redirect_uri` 差一个字符就拒；带 userinfo / 端口不同就拒
- 没有 PKCE 的请求被拒
- code 用第二次被拒，且第一次用过之后行已经不在表里
- refresh 复用 → 整条授权失效
- `groups:send` 默认不在可申请列表里；即使应用被勾了允许，
  用户没有逐群授权时仍然发不出去
- 撤销应用之后，它签出的令牌**立刻**验不过
- 同意页上出现 redirect_uri 的 host（防钓鱼那一条不能只写在文档里）
